# 环境监测管理功能开发计划（Issue 拆分）

> 依据：`PRD-环境监测LIMS产品设计文档.html`、`TRD-环境监测LIMS技术需求文档.html`
> 代码基线：`flow-web`（Vue3 + Vite + Ant Design Vue + Pinia）、`flow-engine`（Spring Boot 3.2 + MyBatis-Plus + SQLite）
> 现状说明：现有 `monitor` 模块为「流程监控」，与本次需求的「环境监测」业务完全无关；本计划为**新增业务域**，统一以表前缀 `ems_` 区分，与既有 `wf_`/`sys_` 隔离。

---

## 0. 总体架构与约定

- **后端包路径**：`com.flow.engine.ems`（controller / service / mapper / entity / dto 均按此路径新增，不污染现有 `engine` 包）。
- **表前缀**：`ems_`。
- **前端路由前缀**：`/ems/*`，权限 key 前缀 `ems:*`。
- **数据落地方式**：环境监测主数据（监测任务、样品、检测数据等）**通过 TRD 定义的「数据模型 + 表单」能力落地**（复用 `wf_data_model` / `wf_form_definition` / `wf_form_data`），流程类业务（采样流转、报告审核）**复用工作流引擎**（复用 `wf_process_*`）。
- **菜单接入**：在 `BasicLayout` 菜单中新增「环境监测」一级菜单，下挂各子模块。

## 2. 各 Issue 详细范围

### ISSUE-EMS-01 环境基础数据管理
**后端（flow-engine）**
- 实体/表：`ems_monitor_point`（监测点：编码、名称、位置、经纬度、类型）、`ems_client`（委托客户）、`ems_detection_method`（检测方法：方法编号、名称、标准依据、检出限）、`ems_standard_limit`（标准限值：污染物、限值、单位）。
- `EmsBaseDataController` + `EmsBaseDataService` + Mapper，提供 CRUD 与下拉查询接口（监测点树、方法下拉）。
- 复用 `sys_dict` 维护「监测类别/样品类型/污染物」等字典项。

**前端（flow-web）**
- `views/ems/basic/`：`monitorPoint.vue`、`client.vue`、`method.vue`、`standard.vue`。
- `api/ems-base.js`：对应接口封装。
- 路由：`/ems/basic/point`、`/ems/basic/client`、`/ems/basic/method`、`/ems/basic/standard`。

### ISSUE-EMS-02 监测任务管理
**后端**
- 表：`ems_monitor_task`（任务编号、委托客户、监测类别、计划开始/结束、状态、负责人）。
- 关联监测点（多对多 `ems_task_point`）、关联检测方法。
- 状态机：草稿→下达→执行中→已完成。

**前端**
- `views/ems/task/`：`task-list.vue`（列表/新增/下达）、`task-detail.vue`。
- `api/ems-task.js`。

### ISSUE-EMS-03 采样与样品管理
**后端**
- 表：`ems_sample`（样品编号、任务ID、监测点、采样时间、采样人、性状、保存条件、条码）、`ems_sample_transfer`（交接记录）。
- 样品条码生成规则（按任务+序号），支持扫码入库（预留接口）。

**前端**
- `views/ems/sample/`：`sample-list.vue`、`sample-register.vue`（登记/打印条码）、`sample-transfer.vue`。
- `api/ems-sample.js`。

### ISSUE-EMS-04 检测数据录入与复核
**后端**
- 表：`ems_test_record`（检测记录：样品ID、方法ID、检测项目、结果值、单位、检出限、是否检出）、`ems_test_review`（复核：复核人、结论、意见）。
- 录入校验：结果必须在方法检出限/量程范围内；超标自动标记。

**前端**
- `views/ems/test/`：`test-input.vue`（按样品批量录入）、`test-review.vue`（复核）。
- `api/ems-test.js`。

### ISSUE-EMS-05 质量控制
**后端**
- 表：`ems_qc_record`（质控类型：空白样/平行样/加标回收/质控样；理论值、实测值、偏差、是否合格）。
- 自动计算平行样相对偏差、加标回收率，与合格阈值比对。

**前端**
- `views/ems/qc/`：`qc-list.vue`、`qc-input.vue`。
- `api/ems-qc.js`。

### ISSUE-EMS-06 报告生成与审核
**后端**
- 表：`ems_report`（报告编号、任务ID、编制人、审核人、批准人、状态、PDF路径）、`ems_report_item`（报告明细引用检测记录）。
- 报告 PDF 生成（复用现有 `jspdf`/后端模板能力，或后端导出）。
- 状态机：编制→审核→批准→签发。

**前端**
- `views/ems/report/`：`report-list.vue`、`report-edit.vue`、`report-preview.vue`。
- `api/ems-report.js`。

### ISSUE-EMS-07 监测数据驾驶舱与统计
**后端**
- `EmsDashboardController`：任务完成率、样品量、超标统计、按监测点/类别聚合。
- 复用 `ProcessMonitorService` 思路，新增 `EmsDashboardService`。

**前端**
- `views/ems/dashboard/index.vue`：卡片 + 图表（任务趋势、超标分布、样品状态）。
- `api/ems-dashboard.js`。

### ISSUE-EMS-08 工作流集成
- 在 `flow-engine` 注册环境流程定义（采样流转、报告审核），通过 `ProcessInstanceService` 发起。
- 前端「任务办理」复用现有 `task/` 模块，环境业务数据通过 `model-data` 动态模型页展示（按 `modelKey=ems_*`）。
- 在 `ModelMenuPermissionService` 中注册 `ems_*` 模型菜单权限。

### ISSUE-EMS-09 权限与菜单接入
- 后端 `Permission` 初始化 `ems:*` 权限项（或随各 Issue 增量注册）。
- 前端 `BasicLayout` 菜单新增「环境监测」分组；`router/index.js` 注册 `/ems/*` 路由并配置 `permKey`。
- 字典项初始化脚本（监测类别、样品类型、污染物等）。

---

## 3. 数据库变更落地
- 新增 `flow-engine/src/main/resources/db/ems_schema.sql`，在 `schema.sql` 末尾通过 `INSERT`/建表语句追加（保持 `continue-on-error` 兼容）。
- 所有 `ems_` 表与既有 `wf_`/`sys_` 表无外键强耦合，通过业务字段（如 `task_id`）关联。

## 4. 实施顺序建议
1. #1 基础数据（地基）
2. #2 → #3 → #4 → #5 → #6（业务主链路）
3. #7 驾驶舱（依赖主链路数据）
4. #8 流程集成（打通工作流）
5. #9 权限菜单（可并行穿插，最后统一收口）

## 5. 验收要点
- 监测任务可下达、样品可登记并打印条码；
- 检测数据录入后可复核、超标自动标记；
- 质控记录计算偏差并判定合格；
- 报告可编制→审核→批准→签发并导出；
- 驾驶舱可展示关键统计；
- 环境业务数据可通过工作流发起并在「我的申请/待办」中办理；
- 权限按 `ems:*` 受控，菜单可见性正确。
