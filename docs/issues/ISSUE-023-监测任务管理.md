## 1. 功能描述

本 Issue 覆盖「委托 → 采样订单 → 调度派单」全链路，是连接基础数据与现场采样的枢纽：

1. **委托单管理（5.1）**
   - 委托详情维护（监测项目、执行标准、频次、样品要求、费用）。
   - **技术确认**：技术室评审方法适用性/实验室能力，出具确认意见；通过则拆单生成采样订单，不通过退回修改。
   - 委托费用与收款（仅接单员以上可见，权限矩阵）。
2. **采样订单管理（5.1 生成 → 5.2 执行）**
   - 订单池按状态流转，承载采样任务容器。
3. **采样调度派单（5.2）**
   - 调度看板按状态列卡片（待派单/已派单/执行中/已送检）。
   - 资源分配（负责人/组员/车辆/设备）+ 冲突检测 + 校准有效期闸门。
   - 派单成功同步微信订阅消息。

**范围边界**：现场外勤采样归 **ISSUE-024**；报告归 **ISSUE-027**。

## 2. 业务规则

| 编号 | 规则 | 说明 |
|------|------|------|
| BR-023-01 | 技术确认守卫 | 委托须技术室确认（t_entrust_review 有意见）方可转「已确认」生成订单 |
| BR-023-02 | 拆单生成订单 | 一个委托可拆多张采样订单（按点位/批次），订单号由编号引擎生成 |
| BR-023-03 | 派单资质闸门 | 派单时校验采样员资质、设备校准有效期，过期/无资质阻断（经 029 规则引擎） |
| BR-023-04 | 资源冲突检测 | 同一人/车/设备在同一时间段不可重复占用，冲突提示 |
| BR-023-05 | 费用可见性 | 金额、收款、发票信息仅业务接单员及以上角色可见 |
| BR-023-06 | 退回重提 | 退回委托修改后可重新提交，保留历史 review 记录 |
| BR-023-07 | 订单最小集 | 订单须含点位、监测项目、计划采样日期，否则不可置「已派单」 |

## 3. 状态机

### 3.1 委托状态机（5.1）
| 当前状态 | 事件 | 目标状态 | 守卫 |
|----------|------|----------|------|
| 草稿 | 提交 | 待技术确认 | 客户/点位/项目齐全 |
| 待技术确认 | 技术确认通过 | 已确认 | t_entrust_review 意见已填（技术室账号） |
| 待技术确认 | 退回 | 已退回 | 必填退回意见 |
| 已退回 | 重新提交 | 待技术确认 | 修改后重提 |
| 已确认 | 生成订单 | （订单态） | 触发拆单 5.2 |

### 3.2 采样订单状态机（5.1+5.2）
| 当前状态 | 事件 | 目标状态 | 守卫 |
|----------|------|----------|------|
| 待派单 | 派单 | 已派单 | 资源已分配且通过 BR-023-03/04 |
| 已派单 | 开始执行 | 采样执行中 | 采样员接受任务（小程序） |
| 采样执行中 | 样品送检 | 样品送检 | 现场采样提交（转 024） |
| 样品送检 | 实验室接收 | 实验室检测中 | 收样通过（转 025/024） |
| 实验室检测中 | 检测完成 | 报告编制 | 批次全合格（转 027） |
| 报告编制 | 归档 | 归档完成 | 报告签发归档（转 027） |

### 3.3 调度派单子状态（5.2）
派单动作内嵌于「待派单 → 已派单」转换，校验失败则保持待派单并提示。

## 4. 业务流程

```
[委托登记(022)] → 提交 → [技术确认(技术室)]
                          ├─通过─▶ [拆单生成采样订单(待派单)]
                          │            │
                          │            ▼
                          │         [调度派单:选单→分配人/车/设备→校验闸门]
                          │            │ 通过
                          │            ▼
                          │         [已派单→采样执行中] ──▶ ISSUE-024 小程序采样
                          └─退回─▶ [已退回] ──修改重提──▶ 技术确认
```

**上游**：ISSUE-022 委托框架。
**下游**：派单完成驱动 ISSUE-024 外勤采样；收样/检测驱动 024/025；归档驱动 027。

## 5. 操作流程

**业务接单员**
1. 「委托管理」打开草稿委托，填写监测项目、执行标准、频次、费用。
2. 提交 → 状态「待技术确认」，等待技术室处理。

**技术室（技术确认）**
1. 受理「待技术确认」委托，评审方法适用性/实验室能力。
2. 出具确认意见（t_entrust_review）；通过 → 系统自动拆单生成采样订单（待派单）；不通过 → 退回并填意见。

**调度员（5.2 派单）**
1. 「采样调度看板」查看「待派单」卡片池。
2. 点选订单 → 派单弹窗分配负责人/组员/车辆/设备。
3. 系统自动校验：资质闸门 + 设备校准有效期 + 资源冲突；通过 → 置「已派单/执行中」，推送微信订阅消息；失败 → 阻断并提示。

## 6. 界面设计

PRD 规范：生态绿主色，状态 Tag 全局一致（待派单=橙 `#F59E0B`、已派单=蓝 `#2563EB`、执行中=蓝、送检=蓝、检测中=蓝、归档=绿）。

- **委托列表页（图 6-2）**：统计卡（待确认/已确认/退回）+ 筛选条 + 表格，状态彩色 Tag。
- **新建委托页（图 6-3）**：分步表单（客户→点位→项目→标准→费用），费用区块按权限显隐。
- **技术确认抽屉**：评审意见输入 + 通过/退回按钮。
- **调度看板（图 6-4）**：按状态分列卡片（待派单/已派单/执行中/已送检），拖拽或点选派单；派单弹窗含资源树 + 冲突高亮 + 校准临期红标。

## 7. 接口设计

**委托（5.1）**
| 接口 | 方法/路径 | 说明 |
|------|-----------|------|
| 委托详情维护 | `/api/v1/entrust/{id}` (GET/PUT) · `/api/v1/entrust/{id}/details` | 项目/标准/费用 |
| 技术确认 | `POST /api/v1/entrust/{id}/tech-confirm` | 写 t_entrust_review，状态机事件 |
| 退回 | `POST /api/v1/entrust/{id}/reject` | 必填意见 |
| 费用 | `/api/v1/entrust/{id}/fee` (GET/PUT) | 受权限控制 |

**采样订单（5.1 生成）**
| 接口 | 方法/路径 | 说明 |
|------|-----------|------|
| 订单拆单生成 | `POST /api/v1/sampling-order/gen?entrustId=` | 委托确认后触发 |
| 订单查询 | `GET /api/v1/sampling-order?status=` | 订单池 |

**调度派单（5.2）**
| 接口 | 方法/路径 | 说明 |
|------|-----------|------|
| 派单 | `POST /api/v1/dispatch` | 分配人/车/设备，触发闸门校验 |
| 派单成员/设备 | `/api/v1/dispatch/{id}/members` · `/devices` | 关联 t_dispatch_member/t_dispatch_device |
| 冲突校验 | `GET /api/v1/dispatch/check?date=&resourceIds=` | 人/车/设备冲突预检 |

## 8. 数据表结构设计

**委托（5.1）**
| 表 | 关键字段 | 说明 |
|----|----------|------|
| t_entrust_detail | id, entrust_id(委托ID), item(监测项目), standard_id(标准方法ID,引用t_standard), freq(频次), sample_req(样品要求), limit_val(限值) | 委托明细（项目/标准） |
| t_entrust_fee | id, entrust_id, total_amount(总额), received(已收), invoice_no(发票号), settle_status(结算状态) | 委托费用（权限可见） |
| t_entrust_review | id, entrust_id, reviewer_id(技术室ID), opinion(确认意见), result(通过/退回), review_at | 技术确认记录 |
| t_sampling_order | id, order_no(订单号,编号引擎), entrust_id, point_id(点位ID), plan_date(计划采样日), status(待派单/已派单/采样执行中/样品送检/实验室检测中/报告编制/归档完成), sampler_lead(负责人) | 采样订单（状态机核心） |

**调度派单（5.2）**
| 表 | 关键字段 | 说明 |
|----|----------|------|
| t_dispatch | id, order_id(订单ID,引用t_sampling_order.id), status(派单状态), dispatch_time(派单时间), plan_start(计划开始), plan_end(计划结束), vehicle_id(车辆ID), note(备注) | 派单主表 |
| t_dispatch_member | id, dispatch_id, emp_id(采样员ID,引用t_employee.id), role(角色:负责/组员) | 派单人员 |
| t_dispatch_device | id, dispatch_id, instrument_id(设备ID,引用t_instrument.id) | 派单设备（校验校准） |

> 关联：t_sampling_order.entrust_id → t_entrust；t_dispatch.order_id → t_sampling_order；资质闸门依赖 ISSUE-030 人员资质表。
