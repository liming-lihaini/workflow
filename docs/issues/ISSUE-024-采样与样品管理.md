## 1. 功能描述

本 Issue 覆盖「现场采样 → 收样分样 → 样品全生命周期 → 留样库」物理样品链路：

1. **微信小程序外勤采样（5.3）**
   - 任务列表拉取（已派单订单）、现场参数填报（时间/GPS 自动）。
   - 现场质控绑定（空白/平行/运输空白）、拍照水印存证。
   - 蓝牙打印条码、一键送检（弱网离线缓存）。
   - 微信扫一扫查样。
2. **收样登记与分样（5.4）**
   - 扫条码 → 带出订单信息 → 核验项勾选 → 通过生成样品记录（检测样派发 / 留样入库）。
   - 拒收登记原因+拍照并通知补采。
3. **样品全生命周期（5.4）**
   - 样品状态机：待收样→已收样→检测中→已完成/待复测/过期作废。
   - 条码编码（原样/分样/留样统一），流转日志。
4. **留样库管理（5.4）**
   - 留样入库、到期预警、销毁审批（固定审批状态机）。

## 2. 业务规则

| 编号 | 规则 | 说明 |
|------|------|------|
| BR-024-01 | 条码唯一 | 每个样品条码全局唯一，由编号引擎生成（原样/分样/留样前缀区分） |
| BR-024-02 | GPS 水印 | 现场照片必须带时间+GPS 水印（微信相机），缺失视为无效存证 |
| BR-024-03 | 离线同步 | 弱网下表单本地缓存，恢复网络自动同步，防数据丢失 |
| BR-024-04 | 收样核验 | 收样须逐项核验（数量/保存条件/标签），不通过则拒收并触发补采通知 |
| BR-024-05 | 拒收留痕 | 拒收必须登记原因+拍照，并推送补采提醒（微信+站内信） |
| BR-024-06 | 留样到期 | 留样到期前定时任务写预警（t_alert），销毁须走审批状态机 |
| BR-024-07 | 样品不可删 | 样品记录不可物理删除，状态置「过期作废」并留日志 |
| BR-024-08 | 现场质控必绑 | 订单含现场质控要求的，采样须绑定现场空白/平行样方可提交送检 |

## 3. 状态机

### 3.1 样品状态机（5.4）
| 当前状态 | 事件 | 目标状态 | 守卫 |
|----------|------|----------|------|
| 待收样 | 扫码收样通过 | 已收样 | 核验项全通过（BR-024-04） |
| 待收样 | 拒收 | （退回补采） | 必填拒收原因+拍照 |
| 已收样 | 派发检测 | 检测中 | 检测任务创建 |
| 检测中 | 检测完成 | 已完成 | 对应批次合格（转025） |
| 检测中 | 质控不合格 | 待复测 | 触发复测（转025/026） |
| 检测中 | 超保存期 | 过期作废 | 定时扫描，不可恢复 |
| 已收样 | 入留样库 | 留样中 | 留样标记 |

### 3.2 留样销毁审批状态机（5.4）
| 当前状态 | 事件 | 目标状态 | 守卫 |
|----------|------|----------|------|
| 留样中 | 申请销毁 | 待审批 | 留样已到期 |
| 待审批 | 审批通过 | 已销毁 | 库管+质量负责人确认 |
| 待审批 | 驳回 | 留样中 | 必填意见 |

### 3.3 小程序采样任务态（5.3）
订单「采样执行中」→ 小程序拉取 → 采样中 → 提交送检（置订单「样品送检」）。

## 4. 业务流程

```
[派单完成(023)] → 小程序拉任务 → [外勤采样:填参+绑质控+拍照+打印条码]
       │                                                    │
       │                                               一键送检
       ▼                                                    ▼
[实验室收样工作台] ← 扫码带出订单 ←─────────────── 送检提醒(微信+站内信)
       ├─核验通过 → 生成样品(检测样派发 / 留样入库)
       └─拒收 → 补采通知
                       │
              ┌────────┴─────────┐
              ▼                  ▼
        [检测中→检测]        [留样库:入库→到期预警→销毁审批]
              │
              ▼
        ISSUE-025 检测数据
```

**上游**：ISSUE-023 派单。
**下游**：检测样驱动 ISSUE-025；留样库受 ISSUE-026 物资/预警联动。

## 5. 操作流程

**采样员（小程序 5.3）**
1. 微信授权登录 → 任务列表查看「已派单/执行中」订单。
2. 进入现场采样：系统自动记录时间+GPS；填写流量/温度/pH/工况/固定剂。
3. 一键添加现场空白/平行样并自动绑定订单。
4. 微信相机拍照（点位/过程/工况，自动水印）。
5. 蓝牙打印样品条码标签；提交送检（离线自动缓存同步）。
6. 微信扫一扫查样，跟踪流转状态。

**样品管理员（5.4 收样/留样）**
1. 收样工作台扫条码 → 带出订单信息 → 逐项核验。
2. 通过 → 生成样品记录（检测样派发检测任务，留样入留样库）；不通过 → 拒收登记原因+拍照+通知补采。
3. 留样库：登记入库（库位/到期日）；到期收到预警 → 发起销毁审批 → 审批通过后销毁。

## 6. 界面设计

PRD 规范：小程序大按钮卡片式任务流；PC 端生态绿主色、状态 Tag。

- **小程序任务列表（图 6-5）**：卡片式（待办/进行中/已送检），大按钮「开始采样/提交送检」。
- **现场采样记录**：表单（时间/GPS 自动锁定）+ 现场质控快捷添加 + 拍照墙（水印预览）+ 蓝牙打印按钮。

## 7. 接口设计

**小程序采样（5.3）**
| 接口 | 方法/路径 | 说明 |
|------|-----------|------|
| 任务拉取 | `GET /api/v1/wx/sampling-tasks?empId=` | 已派单订单 |
| 采样记录提交 | `POST /api/v1/wx/sampling-record` | 现场参数+GPS |

**收样 / 样品 / 留样（5.4）**
| 接口 | 方法/路径 | 说明 |
|------|-----------|------|
| 收样核验 | `POST /api/v1/sample/receive` | 扫码核验，生成样品 |

| 留样销毁审批 | `POST /api/v1/retain/{id}/destroy-apply` · `/approve` | 审批状态机 |

## 8. 数据表结构设计

**小程序采样（5.3）**
| 表 | 关键字段 | 说明 |
|----|----------|------|
| t_sampling_record | id, order_id(订单ID), sampler_id(采样员), sample_time(采样时间), gps_lng, gps_lat, temp(温度), ph, flow(流量), condition(工况), fixative(固定剂), status | 电子采样记录 |
| t_sample_qc_binding | id, order_id, qc_type(现场空白/平行/运输空白), sample_id(绑定样品), bind_time | 现场质控绑定 |
| t_photo | id, biz_type, biz_id, file_meta_id(引用t_file_meta), watermark(水印信息:时间+GPS), shoot_time | 照片存证（WORM） |

**收样 / 样品 / 留样（5.4）**
| 表 | 关键字段 | 说明 |
|----|----------|------|
| t_sample | id, barcode(条码,编号引擎), order_id, point_id, item(项目), sample_type(原样/分样/留样), status(待收样/已收样/检测中/待复测/已完成/过期作废), retain_flag(是否留样), preserve_cond(保存条件), expire_at(失效时间) | 样品主表（状态机核心） |
| t_sample_log | id, sample_id, op_type(收样/派发/复测/作废), op_by, op_at, remark | 样品流转日志（不可删） |
| t_retain | id, sample_id, store_loc(库位), in_time(入库时间), expire_date(到期日), status(留样中/待审批/已销毁), apply_by, approve_by, approve_at | 留样库记录（销毁审批状态机） |

> 关联：t_sample.order_id → t_sampling_order；t_retain.sample_id → t_sample；条码由 ISSUE-029 编号引擎统一生成。
