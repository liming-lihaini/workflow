> **说明**：原「工作流集成」Issue 依据 TRD 第 4/5 章明确结论**不引入工作流引擎**（BPMN/Activiti 等），改用**固定状态机硬编码**。本 Issue 重构为「状态机与规则引擎基础底座」，为 022~028 提供统一的流程/规则/编号/计算能力。

---

## 1. 功能描述

本 Issue 是横切所有业务模块的技术底座，提供四类可复用能力：

1. **固定状态机框架**：轻量状态机引擎（状态/事件/守卫 Guard），以配置+硬编码方式驱动各业务状态机（委托/订单/样品/批次/报告/仪器/计划等），不依赖外部工作流引擎。
2. **规则引擎（QLExpress）**：基于 QLExpress 的规则执行框架，承载资质闸门、物资校准闸门、超标判定、质控判定等业务规则，规则可配置化。
3. **编号规则引擎**：统一生成业务单号（委托号/订单号/样品条码/批次号/报告号等），支持前缀+日期+序列，保证全局唯一。
4. **公式计算引擎**：基于 QLExpress 执行检测结果公式运算（联动 025 标准库 formula 字段），单位换算。

**设计原则**：固定状态机硬编码（TRD 明确），规则可配置但不引入图形化流程编排；SQLite + 应用内缓存；审计 WORM 贯穿。

## 2. 业务规则

| 编号 | 规则 | 说明 |
|------|------|------|
| BR-029-01 | 不引入工作流引擎 | 采用固定状态机硬编码，避免重流程编排复杂度（TRD 决策） |
| BR-029-02 | 守卫必校验 | 状态迁移前必须执行 Guard，Guard 失败阻断并回滚 |
| BR-029-03 | 规则可配置 | 资质/物资/超标/质控规则以表达式存储，QLExpress 执行，支持热更新 |
| BR-029-04 | 编号唯一 | 编号引擎保证全局唯一，序列按业务+日期分段 |
| BR-029-05 | 公式安全 | 公式计算引擎沙箱执行，禁止危险 API 调用 |
| BR-029-06 | 状态不可跳变 | 仅允许状态机定义的有向迁移，禁止越级 |
| BR-029-07 | 操作审计 | 所有状态事件/规则执行写入 t_operation_log（WORM） |

## 3. 状态机

本 Issue 提供**状态机框架**而非具体业务状态机。框架定义：

| 组件 | 说明 |
|------|------|
| State | 业务状态枚举（各模块自定义，如委托:草稿/待技术确认/已确认/已退回） |
| Event | 触发事件（提交/确认/派单/收样/锁定/签发等） |
| Guard | 守卫条件（表达式/函数，如"资源校验通过"、"整批合格"） |
| Transition | 迁移定义（当前态+事件+目标态+Guard） |

**框架内置校验状态机（通用）**
| 当前状态 | 事件 | 目标状态 | 守卫 |
|----------|------|----------|------|
| 任意 | 非法迁移 | 拒绝 | Guard=状态机未定义该迁移 |
| 待校验 | 校验通过 | 通过 | Guard=规则引擎返回 true |
| 待校验 | 校验失败 | 拒绝 | Guard=规则引擎返回 false，记录原因 |

各业务模块的具体状态机在 022~028 中定义，本框架负责驱动与守卫执行。

---

## 4. 业务流程

```
[业务模块触发状态事件] → [状态机框架:查迁移+执行Guard]
       │                              │
       │ Guard 失败              Guard 成功
       ▼                              ▼
   [阻断+回滚+提示]              [状态落库+写审计]
       
[规则执行请求] → [QLExpress 规则引擎:取表达式→沙箱执行→返回布尔/值]
[编号请求] → [编号引擎:前缀+日期+序列→返回唯一号]
[公式计算请求] → [公式引擎:取 formula→沙箱计算→返回结果]
```

**上游**：无。
**下游**：被 023（订单/派单状态机、资质闸门）、024（样品状态机、条码）、025（批次状态机、公式/质控规则）、026（仪器/危化品/计划状态机、物资闸门）、027（报告审核状态机、编号）、028（统计）全面依赖。

## 5. 操作流程

**后端开发**
1. 在状态机配置中注册各模块状态/事件/Guard（硬编码或配置表）。
2. 在规则配置中维护 QLExpress 表达式（资质/物资/超标/质控）。
3. 调用编号引擎 API 生成各业务单号；调用公式引擎执行计算。

**业务模块开发**
1. 触发状态事件时调用 `StateMachine.fire(bizType, bizId, event)`，由框架执行 Guard 与落库。
2. 引用规则引擎做闸门校验（如派单前 `RuleEngine.eval("dispatch_gate", context)`）。

## 6. 界面设计

本 Issue 为**后端基础设施**，无独立业务界面。提供：

- **规则配置后台**（可选）：规则表达式列表/编辑（仅管理员），用于维护 QLExpress 规则。
- **状态迁移监控**（可选）：查看各业务状态分布（消费 028 大屏能力）。
- 错误提示统一格式（Guard 失败原因回显到业务页面）。

## 7. 接口设计

| 接口 | 方法/路径 | 说明 |
|------|-----------|------|
| 状态迁移 | `POST /api/v1/statemachine/fire` (body: bizType,bizId,event,ctx) | 驱动状态机+Guard |
| 状态查询 | `GET /api/v1/statemachine/state?bizType=&bizId=` | 当前状态 |
| 规则执行 | `POST /api/v1/rule/eval` (body: ruleKey,context) | QLExpress 规则求值 |
| 编号生成 | `GET /api/v1/seq/next?biz=order` | 返回唯一单号 |
| 公式计算 | `POST /api/v1/calc` (body: formula,params) | 公式引擎计算 |
| 规则配置 | `/api/v1/rule` (GET/POST/PUT) | 规则维护（管理员） |

## 8. 数据表结构设计

> 状态机/规则以**硬编码 + 轻量配置**为主，数据库仅存必要配置与审计。

| 表 | 关键字段 | 说明 |
|----|----------|------|
| t_state_def | id, biz_type(业务类型), state_key, state_name, sort | 状态定义（可选配置） |
| t_transition_def | id, biz_type, from_state, event, to_state, guard_expr(Guard表达式) | 迁移定义（固定状态机） |
| t_rule_def | id, rule_key(规则标识:dispatch_gate等), rule_name, expr(QLExpress表达式), enabled(启用), version | 规则定义（可配置热更） |
| t_seq_def | id, biz_key(业务键), prefix(前缀), seq_date(日期段), current_val(当前序列), step(步长) | 编号序列定义 |
| t_operation_log | id, biz_type, biz_id, action(动作), operator_id, op_at, detail(详情), hash(防篡改哈希) | 操作审计（WORM，不可删） |

> 关联：t_operation_log 由所有模块状态事件统一写入（与 030 审计共享）；t_rule_def.expr 由 QLExpress 沙箱执行；编号由 t_seq_def 分段生成。
