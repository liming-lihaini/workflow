## 1. 功能描述

本 Issue 是实验室检测环节的核心，实现「标准库 → 原始数据录入 → 公式自动运算 → 超标预警 → 质控判定 → 数据锁定」的闭环：

1. **标准库管理（t_standard）**：监测项目、标准方法、检出限、单位、限值、计算公式（QLExpress 表达式）。
2. **检测批次（t_test_batch）**：按样品/项目归集检测任务，状态机管控。
3. **原始数据录入（t_test_record）**：手工录入 / Excel 导入，资质闸门（人员×项目×方法）。
4. **自动运算**：公式引擎调用 QLExpress 计算最终结果，单位换算。
5. **超标预警**：结果超 t_standard.limit_val 自动标红 `#E02424` + ▲，写 t_alert。
6. **质控判定（t_qc_record）**：规则引擎判定合格/异常；不合格则数据锁定 + 强制异常说明/复测。
7. **数据锁定**：整批合格方可流转报告编制（转 027）。

## 2. 业务规则

| 编号 | 规则 | 说明 |
|------|------|------|
| BR-025-01 | 资质闸门 | 检测员仅可录入已授权「人员×项目×方法」数据，未授权拦截（029 规则引擎） |
| BR-025-02 | 公式运算 | 最终结果由 QLExpress 公式引擎基于原始值计算，禁止手工改结果值 |
| BR-025-03 | 超标标红 | result > limit_val 自动标红加粗 + ▲，报告同步标注 |
| BR-025-04 | 整批合格 | 批次内所有记录质控判定合格，批次方可置「待报告/已锁定」 |
| BR-025-05 | 锁定不可改 | 批次「已锁定」后原始数据只读，修改需走复测/版本变更 |
| BR-025-06 | 异常必说明 | 质控不合格必须填写异常说明或发起复测，否则不可锁定 |
| BR-025-07 | 批次关联 | 检测记录必须归属某批次（t_test_batch），批次关联订单/样品 |
| BR-025-08 | 单位一致 | 录入单位须与标准库单位一致，不一致触发换算提示 |

## 3. 状态机

### 3.1 检测批次状态机（5.6）
| 当前状态 | 事件 | 目标状态 | 守卫 |
|----------|------|----------|------|
| 待录入 | 开始录入 | 计算中 | 批次已创建且分配检测员 |
| 计算中 | 公式运算完成 | 质控判定中 | 全部原始值已录入 |
| 质控判定中 | 全部合格 | 待报告 | BR-025-04 整批合格 |
| 质控判定中 | 存在不合格 | 已锁定(待复测) | BR-025-06 异常说明/复测 |
| 待报告 | 锁定 | 已锁定 | 整批合格，流转报告编制 |
| 已锁定(待复测) | 复测合格 | 已锁定 | 复测记录合格 |

### 3.2 检测记录态（5.6）
单条 t_test_record 由录入 → 计算 → 判定（合格/异常），异常触发批次锁定。

## 4. 业务流程

```
[样品检测中(024)] → 创建检测批次 → [检测员领任务(资质闸门)]
       │
       ▼
[原始数据录入(手工/Excel)] → [公式引擎计算] → [超标判定(标红+预警)]
       │
       ▼
[规则引擎质控判定] ──合格──▶ [批次合格→锁定→待报告] ──▶ ISSUE-027 报告
       │
       不合格
       ▼
[数据锁定 + 异常说明/复测] ──复测合格──▶ 锁定待报告
                                   └─复测仍不合格─▶ 留痕，转 026 质控
```

**上游**：ISSUE-024 样品「检测中」。
**下游**：批次锁定驱动 ISSUE-027 报告编制；异常联动 ISSUE-026 质控与 ISSUE-030 资质。

## 5. 操作流程

**检测员**
1. 「检测管理 → 我的批次」领取「待录入」批次（资质闸门校验）。
2. 录入原始数据（手工或 Excel 导入），保存后系统自动公式运算。
3. 查看结果：超标自动标红 + ▲；查看质控判定结论。
4. 若质控不合格：填写异常说明或发起复测；复测合格后批次方可锁定。
5. 整批合格后批次置「待报告/已锁定」，提交报告编制。

**审核员（复核）**
1. 「检测管理 → 待复核」查看批次数据与质控结论（◐ 复核权限）。
2. 确认数据合理性，可退回检测员补充说明。

## 6. 界面设计

PRD 规范：超标标红加粗 + ▲；检测管理导航高亮；状态 Tag。

- **检测数据录入页（图 6-8）**：左侧批次/样品树，右侧录入表（原始值列 + 自动计算结果列 + 判定列）；超标行红底加粗 ▲。
- **质控异常弹窗**：不合格时弹出，强制填写异常说明 / 选择复测，否则不可关闭。
- **标准库维护页**：项目/方法/检出限/单位/限值/公式表达式编辑器（QLExpress 语法提示）。
- **批次看板**：按状态（待录入/计算中/质控判定中/待报告/已锁定）分列，统计卡显示合格率。

## 8. 数据表结构设计

| 表 | 关键字段 | 说明 |
|----|----------|------|
| t_standard | id, item(监测项目), method(标准方法), std_no(标准号), detect_limit(检出限), unit(单位), limit_val(限值), formula(QLExpress公式), precision(保留位数) | 标准库（公式引擎数据源） |
| t_test_batch | id, batch_no(批次号,编号引擎), order_id, sample_id, item, standard_id, status(待录入/计算中/质控判定中/待报告/已锁定), operator_id(检测员), lock_at(锁定时间) | 检测批次（状态机核心） |
| t_test_record | id, batch_id(批次ID), sample_id, original_val(原始值), result_val(结果值,公式算), unit, over_flag(超标标记), qc_result(合格/异常), abnormal_note(异常说明), input_by, input_at | 检测原始/结果记录 |
| t_qc_record | id, batch_id, qc_type(平行/加标/空白等), expected_val, actual_val, deviation(偏差), pass_flag(合格), judge_by, judge_at | 质控判定记录 |

> 关联：t_test_batch.sample_id → t_sample；t_test_record.batch_id → t_test_batch；t_qc_record.batch_id → t_test_batch；formula 由 ISSUE-029 公式引擎执行。
