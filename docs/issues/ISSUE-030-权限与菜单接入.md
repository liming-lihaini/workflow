## 1. 功能描述

本 Issue 是系统安全与访问控制的底座，覆盖「人员资质 → RBAC 权限 → 菜单路由 → 审计」：

1. **人员与资质（5.9）**：员工档案、检测资质（人员×项目×方法授权）、资质矩阵，资质闸门数据源。
2. **RBAC 权限（5.10）**：用户/角色/权限（user:add 等）、角色-权限关联、数据范围（本人/本部门/全部）。
3. **后台管理（5.10）**：部门（022 已建）、字典（022 已建）、集成配置（022 已建）、登录日志、操作日志只读查询。
4. **菜单路由接入**：前端按角色动态渲染左侧导航与路由权限（依据权限矩阵 13 模块）。
5. **审计 WORM（5.9/5.10）**：操作日志/登录日志不可删改，满足合规。

**范围边界**：部门/字典/集成配置表在 022 定义，本 Issue 负责其权限控制与界面接入；RBAC 核心表由 5.10 维护。

## 2. 业务规则

| 编号 | 规则 | 说明 |
|------|------|------|
| BR-030-01 | 资质授权粒度 | 检测资质授权到「人员×项目×方法」，未授权即拦截录入/派单（029 闸门） |
| BR-030-02 | 权限矩阵硬约束 | 9 角色 × 13 模块权限严格按 PRD 第 7 章矩阵控制 |
| BR-030-03 | 审计不可删 | t_operation_log / t_login_log 任何角色不可删除修改（WORM） |
| BR-030-04 | 数据范围 | 角色 data_scope:1 本人/2 本部门/3 全部，控制数据可见性 |
| BR-030-05 | 账号锁定 | 连续 5 次登录失败锁定，写登录日志 |
| BR-030-06 | 涉密授权 | 涉密监测数据需单独授权方可查看/导出，导出动作全部留痕 |
| BR-030-07 | 资质联动 | 能力验证/比对不合格触发资质复核（026→030） |

## 3. 状态机

本 Issue 为**配置/控制型**，无业务状态机。人员资质状态（有效/失效/复核中）为轻量标记：

| 当前状态 | 事件 | 目标状态 | 守卫 |
|----------|------|----------|------|
| 有效 | 资质复核不通过 | 失效 | 026 能力验证不合格触发 |
| 失效 | 复核恢复 | 有效 | 重新授权 |
| 有效 | 发起复核 | 复核中 | 定期/触发复核 |

## 4. 业务流程

```
[员工入职] → [维护人员档案+检测资质(人员×项目×方法)]
       │
       ├─▶ [RBAC:建用户→绑角色→配权限] → [前端菜单按角色渲染]
       │
       ├─▶ [资质闸门数据源] ──引用──▶ 023 派单/025 录入/026 能力画像
       │
       └─▶ [操作/登录] → [写审计 WORM(t_operation_log/t_login_log)]
```

**上游**：022 部门/字典。
**下游**：资质闸门约束 023/025/026；权限矩阵约束全模块菜单与接口。

---

## 5. 操作流程

**系统管理员**
1. 「人员管理」维护员工档案，配置检测资质（人员×项目×方法授权矩阵）。
2. 「系统设置 → 用户/角色/权限」创建账号、绑定角色、配置权限项（增删改查导印审）。
3. 「系统设置 → 登录日志/操作日志」查看审计（只读，不可删）。
4. 处理资质复核：能力不足员工置失效。

**各角色用户**
1. 登录后前端按角色动态渲染左侧导航（菜单路由权限）。
2. 在权限范围内操作，越权动作被 `@RequirePerm` 拦截。

---

## 6. 界面设计

PRD 规范：生态绿主色；左侧一级导航 + 面包屑；状态 Tag。

- **权限矩阵页**：13 模块 × 9 角色网格（● 完整 / ◐ 部分 / — 无），可逐项配置。
- **人员资质页**：员工列表 + 资质矩阵（人员×项目×方法勾选），失效红标。
- **角色/权限页**：角色树 + 权限项分组（增删改查导印审）勾选。
- **审计日志页**：登录日志/操作日志表格（只读，无删除按钮，WORM 标识）。
- **前端菜单**：按角色动态显示导航项（客户/委托/采样调度/小程序/收样/检测/质控/物资/报告/档案/统计/系统设置/SOP）。

## 7. 接口设计

**人员资质（5.9）**
| 接口 | 方法/路径 | 说明 |
|------|-----------|------|
| 员工 CRUD | `/api/v1/employees` (GET/POST/PUT) | 人员档案 |
| 资质维护 | `/api/v1/employees/{id}/qualifications` (GET/POST/PUT) | 人员×项目×方法 |
| 资质校验 | `GET /api/v1/qualification/check?emp=&item=&method=` | 闸门查询 |

**RBAC（5.10）**
| 接口 | 方法/路径 | 说明 |
|------|-----------|------|
| 用户 CRUD | `/api/v1/admin/users` (GET/POST/PUT/DELETE) | 账号（状态/锁定） |
| 角色 CRUD | `/api/v1/admin/roles` (GET/POST/PUT) | 角色+data_scope |
| 权限树 | `GET /api/v1/admin/permissions` | 权限树（分组） |
| 角色权限绑定 | `/api/v1/admin/role-permissions` (POST/PUT) | 关联 |
| 菜单路由 | `GET /api/v1/menu?role=` | 动态菜单 |

**审计/日志（5.10）**
| 接口 | 方法/路径 | 说明 |
|------|-----------|------|
| 登录日志 | `GET /api/v1/admin/login-log?page=` | 登录审计 |
| 操作日志 | `GET /api/v1/admin/operation-log?page=` | WORM 只读 |

> 全部接口受 `@RequirePerm` 保护；operation-log 仅读，DELETE 被服务端拒绝（WORM）。

## 8. 数据表结构设计

**人员资质（5.9）**
| 表 | 关键字段 | 说明 |
|----|----------|------|
| t_employee | id, emp_no(工号), name(姓名), dept_id(部门ID,引用t_department), post(岗位), status(状态) | 员工档案 |
| t_employee_qualification | id, emp_id(员工ID), item(检测项目), method(标准方法), status(有效/失效/复核中), valid_from, valid_to, granted_by | 检测资质（人员×项目×方法） |
| t_operation_log | id, biz_type, biz_id, action, operator_id, op_at, detail, hash(防篡改) | 操作审计（WORM，不可删） |

**RBAC（5.10）**
| 表 | 关键字段 | 说明 |
|----|----------|------|
| t_user | id, username, password(bcrypt哈希), emp_id, dept_id, status(启用/禁用/锁定), fail_count, lock_time, last_login | 登录账号（RBAC 主体） |
| t_role | id, role_name, role_key(SUPER_ADMIN/SAMPLER等), data_scope(1本人/2本部门/3全部), status | 角色 |
| t_permission | id, perm_key(user:add等), perm_name, perm_group(增删改查导印审) | 权限项 |
| t_role_permission | id, role_id, permission_id | 角色-权限关联 |
| t_login_log | id, user_id, username, ip, terminal(PC/微信), login_time, success, fail_reason | 登录日志（不可删） |

> 关联：t_user.emp_id → t_employee；t_employee_qualification 经 029 闸门约束 023/025；t_department/t_data_dict 表在 022 定义、本模块引用。RBAC 核心表由 5.10 统一维护，5.9 资质矩阵引用构建权限。
