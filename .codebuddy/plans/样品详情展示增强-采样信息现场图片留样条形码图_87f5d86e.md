## 用户需求

在「样品详细信息」抽屉中，完整展示样品的采样信息、现场图片、留样信息，并生成并展示样品条形码图。

## 产品概述

当前样品详情抽屉（Sample.vue 中 `样品详情`）仅展示样品基本字段、质控样列表、操作日志。需扩展为包含四个核心分区：条形码图、采样信息、现场图片、留样信息，形成一个完整的样品全生命周期详情视图。

## 核心功能

- 条形码图：基于样品条码（如 YP202608060001）使用 JsBarcode 以 CODE128 渲染为可视图（canvas/svg），替换原有纯文本展示。
- 采样信息：展示采样来源、样品编号、检测类别、检测项目、采样参数、固定剂、现场质控方式、采样天气、采样人、采样时间等（来源于 `detail.sample` 与 `detail.record`）。
- 现场图片：从 `detail.sample.samplePhoto`（逗号分隔的相对路径）拆分，拼接为访问 URL（`/api/v1/ems/base/sampling/samples/photo/{path}`），以缩略图网格展示，支持点击放大预览。
- 留样信息：展示是否留样、留样天数、留样人、留样日期、存放位置、留样到期日（来源于 `detail.sample` 的留样字段）。

## 技术栈

- 前端框架：Vue 3 + TypeScript（`<script setup>`，项目实际为 JS 但沿用现有模式）
- UI 组件库：ant-design-vue 4.x（沿用 a-drawer / a-descriptions / a-image / a-divider 等现有组件）
- 条形码库：JsBarcode（前端新增依赖，用户已确认方案）
- 数据请求：现有 axios 实例 `request`（baseURL `/api/v1`）
- 无需后端改动：`getSampleDetail` 已返回全部所需字段

## 实现方案

### 总体策略

在现有 `Sample.vue` 的详情抽屉模板中，按顺序排列四个分区（条形码图 → 采样信息 → 现场图片 → 留样信息，原质控样、操作日志保留）。前端从 `detail.sample.samplePhoto` 拆分出图片路径数组，使用计算属性生成可访问 URL 列表；条形码使用 JsBarcode 在 `onMounted`/`watch(detail)` 时渲染到 `<svg>` 或 `<canvas>` 引用。

### 关键技术决策

1. **条形码用 JsBarcode + SVG（非 canvas）**：SVG 矢量清晰、无需额外依赖、易于打印/导出，且 JsBarcode 对 CODE128 支持成熟。在 `watch` 到 `detail.sample.barcode` 变化时调用 `JsBarcode(ref, code, {format:'CODE128'})`。
2. **现场图片来源用 `detail.sample.samplePhoto`**：经确认上传接口仅把路径写入 `sample.samplePhoto` 字段（逗号分隔），未写入 `t_photo` 表，因此 `sampleDetail` 返回的 `photos` 列表可能为空。前端使用 `samplePhoto` 拆分拼接，保证回显正确（避免图片加载不出来的回归问题）。
3. **图片预览复用 antd `a-image` 或现有 modal**：用 `a-image` 组件直接支持缩略图网格与点击放大，减少自定义 modal 逻辑，与现有 `picture-card` 风格一致。
4. **不修改后端**：所有数据已齐备，避免扩大改动范围与回归风险。

### 性能与可靠性

- 图片列表为少量（现场照片一般 <20 张），用 `v-for` + `a-image` 懒加载即可，无性能问题。
- 条形码渲染放在 `watch(detail)` 中，detail 关闭时 `detail=null` 不渲染，避免空引用报错；加 `nextTick` 确保 DOM 就绪后再渲染。
- 图片 URL 拼接使用计算属性缓存，避免重复计算。

## 实现注意事项

- 复用现有 `api` 常量与 `getSampleDetail` 调用（已在 `openDetail` 中调用），无需新增请求。
- JsBarcode 通过 `npm install jsbarcode` 安装并在 `package.json` 登记；注意项目为 `type: module`，导入用 `import JsBarcode from 'jsbarcode'`。
- 采样参数 `sampleParams` 为 JSON 字符串，需 `JSON.parse` 后展示（try-catch 容错，解析失败显示原值）。
- 字段展示注意空值兜底（用 `|| '-'` 或 `a-empty`），保持原详情页风格。
- 不影响现有上传/收集流程与其图片加载逻辑。

## 关键代码结构

```js
// Sample.vue script 片段（示意）
import JsBarcode from 'jsbarcode'

const barcodeRef = ref(null)
const detail = ref(null)

const photoList = computed(() => {
  const raw = detail.value?.sample?.samplePhoto
  if (!raw) return []
  return raw.split(',').filter(Boolean).map(p => `/api/v1/ems/base/sampling/samples/photo/${p}`)
})

const sampleParams = computed(() => {
  const raw = detail.value?.sample?.sampleParams
  if (!raw) return []
  try { return JSON.parse(raw) } catch { return [] }
})

watch(() => detail.value?.sample?.barcode, (code) => {
  if (code && barcodeRef.value) {
    nextTick(() => JsBarcode(barcodeRef.value, code, { format: 'CODE128', width: 2, height: 50, displayValue: true }))
  }
})
```

## 设计风格

在现有样品详情抽屉（a-drawer，宽度 720）基础上扩展，保持与项目一致的简洁企业风格（ant-design-vue 默认主题）。采用分区卡片化呈现：顶部条形码图居中对齐并配样品名称，其下依次为「采样信息」「现场图片」「留样信息」「质控样」「操作日志」分区，每个分区用 `a-divider` 标题 + `a-descriptions` 或图片网格，视觉层次清晰、信息密度合理。

## 页面区块设计（样品详情抽屉，自上而下）

1. 条形码区：居中展示 SVG 条形码图，下方显示条码文本与样品名称，带浅色边框卡片。
2. 采样信息区：`a-descriptions` 两列展示来源/样品编号/检测类别/检测项目/采样天气/采样人/采样时间，采样参数以子列表展示。
3. 现场图片区：`a-image` 缩略图网格（每行多张），空时显示 `a-empty`。
4. 留样信息区：`a-descriptions` 两列展示是否留样/留样天数/留样人/留样日期/存放位置/留样到期。
5. 质控样区、操作日志区：保持原有展示。
