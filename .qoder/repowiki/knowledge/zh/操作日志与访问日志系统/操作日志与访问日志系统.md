## 日志系统概述

该项目采用**双轨制日志体系**：基于 Spring AOP 的**操作日志（OperationLog）**和基于 Servlet Interceptor 的**访问日志（AccessLog）**，所有日志持久化到 SQLite 数据库，并提供统一的查询、导出和管理 API。

## 核心架构

### 1. 访问日志（AccessLog）
- **采集方式**：`AccessLogInterceptor` 通过 `HandlerInterceptor` 拦截所有 HTTP 请求
- **记录内容**：用户ID、用户名、IP、User-Agent、URL、HTTP方法、查询参数、响应状态码、错误信息、访问时间
- **实现位置**：`interceptor/AccessLogInterceptor.java`
- **实体模型**：`entity/AccessLog.java` → 表 `sys_access_log`

### 2. 操作日志（OperationLog）
- **采集方式**：`@OpLog` 注解 + `OperationLogAspect` AOP 切面，标注在 Controller 方法上自动记录
- **记录内容**：模块名、操作类型、方法名、请求参数、返回结果、修改前后数据、用户信息、IP、操作时间
- **实现位置**：`annotation/OpLog.java` + `aspect/OperationLogAspect.java`
- **实体模型**：`entity/OperationLog.java` → 表 `sys_operation_log`
- **支持特性**：可配置是否记录参数、结果、修改前后数据

### 3. 统一服务层
- **LogService**：封装日志的增删查改、分页查询、条件过滤、导出、过期清理等功能
- **Web 接口**：`controllers/LogController.java` 提供 `/api/v1/system/logs` 系列 RESTful API

## 技术栈
- **日志框架**：SLF4J + Logback（通过 Lombok `@Slf4j` 注入）
- **AOP 框架**：Spring AspectJ
- **数据存储**：MyBatis-Plus + SQLite
- **注解驱动**：自定义 `@OpLog` 注解实现声明式日志记录

## 设计模式与约定

### 日志字段规范
- 所有日志实体均包含用户标识（userId、username）、IP、时间戳等审计必需字段
- 操作日志支持 beforeData/afterData 对比，便于追踪数据变更
- 访问日志通过 HTTP 状态码区分成功/失败（result: 0=失败, 1=成功）

### 异常安全
- 日志记录过程被 try-catch 包裹，确保日志失败不影响主业务流程
- Token 验证失败时优雅降级，不记录用户信息但继续记录请求

### 性能考虑
- 访问日志在 `afterCompletion` 中异步记录，避免阻塞请求处理
- 支持按时间范围分页查询和导出，避免大数据量性能问题

## 开发者规范
1. **需要记录业务操作**：在 Controller 方法上添加 `@OpLog(module="模块名", operation="操作类型")`
2. **需要记录请求参数/结果**：设置 `recordParams=true` / `recordResult=true`
3. **需要记录数据变更**：配合 `setBeforeData()` 使用 `recordBeforeData=true` 和 `recordAfterData=true`
4. **禁止直接操作 Mapper**：统一通过 `LogService` 进行日志操作
5. **日志级别**：调试信息用 `log.debug`，警告用 `log.warn`，错误用 `log.error`
