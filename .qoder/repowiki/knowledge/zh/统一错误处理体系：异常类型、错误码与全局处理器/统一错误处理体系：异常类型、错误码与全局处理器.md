该流程引擎项目在后端（Spring Boot）中建立了一套完整的统一错误处理体系，涵盖错误码定义、业务异常封装、全局异常拦截和标准化响应结构。

**1. 核心架构**
- 所有 REST 接口返回体统一为 `Result<T>` 结构，包含 code、message、data、requestId、timestamp 字段
- 错误码通过 `ErrorCode` 枚举集中管理，采用分层编码策略：0 表示成功，4xx 为客户端错误，5xx 为系统错误，1xxx 为业务错误
- 使用 Spring 的 `@RestControllerAdvice` + `@ExceptionHandler` 实现全局异常拦截

**2. 异常类型设计**
- `BusinessException`：通用业务异常，适用于控制器层和业务校验场景
- `FlowException`：流程引擎专用异常，框架内部和节点处理器统一抛出此异常
- 两者都继承自 `RuntimeException`，支持携带 ErrorCode 或自定义消息

**3. 全局异常处理器**
`GlobalExceptionHandler` 统一处理以下异常类型：
- `BusinessException` → 返回 Result.fail(code, message)
- `NoHandlerFoundException` → 404 资源不存在
- `MethodArgumentNotValidException` → 参数校验失败，提取具体字段错误信息
- 其他 `Exception` → 记录日志并返回系统错误

**4. 使用规范**
- 业务逻辑中的校验失败应抛出 `BusinessException(ErrorCode.XXX)`
- 流程引擎内部错误应抛出 `FlowException(ErrorCode.XXX)`
- 避免在业务代码中直接返回 Result，让全局处理器统一转换
- 错误码必须先在 `ErrorCode` 中定义，禁止硬编码数字

**5. 前端错误处理**
前端通过统一的请求封装处理后端返回的 Result 结构，根据 code 判断成功/失败状态。
