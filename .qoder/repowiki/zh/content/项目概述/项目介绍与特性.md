## 项目概述

本项目是一个企业级工作流引擎解决方案，采用前后端分离架构，提供完整的可视化流程设计、轻量级流程执行引擎、任务管理中心、RBAC权限控制以及监控审计等能力。项目旨在为企业级业务流程自动化提供低成本、高可控的解决方案。

### 核心价值主张

- **低代码+可插拔架构**：通过节点处理器注册机制实现高度可扩展的运行时行为，降低定制成本
- **轻量化设计**：基于自定义解析器与节点处理器，避免重型规则引擎带来的复杂度
- **强扩展性**：新增节点类型只需实现对应处理器并注册，无需修改核心调度逻辑
- **完善的可观测性**：内置访问日志、操作日志、流程监控与 Webhook 回调，满足合规与排障需求
- **贴近业务场景**：表单与数据模型联动、动态表达式计算、条件网关与并行网关等常用模式开箱即用

### 与传统工作流引擎对比优势

| 特性 | 传统工作流引擎 | 本方案 |
|------|---------------|--------|
| 运行时重量 | 重型，依赖复杂规则引擎 | 轻量，自定义解析器驱动 |
| 扩展方式 | 侵入式改造，修改核心逻辑 | 非侵入式，处理器注册机制 |
| 部署复杂度 | 高，需要额外中间件 | 低，Spring Boot单体部署 |
| 学习曲线 | 陡峭，需要专业工作流知识 | 平缓，可视化设计降低门槛 |
| 监控审计 | 需要额外集成 | 内置完善的监控审计体系 |
| 权限控制 | 基础RBAC支持有限 | 三员管理+数据权限精细化控制 |

## 技术架构

### 技术栈概览

**后端技术栈**
- **框架**：Spring Boot 2.x + MyBatis-Plus

- **缓存**：Redis（可选，用于会话和缓存）

- **版本控制**：Git + GitHub Actions
- **代码质量**：SonarQube + ESLint + Prettier
- **文档生成**：Swagger + JSDoc

## 核心特性

### 可视化流程设计
- **拖拽式设计器**：支持用户任务、服务任务、脚本任务、子流程、各种网关等节点类型
- **实时预览**：设计过程中实时验证流程语法和逻辑正确性
- **版本管理**：支持流程定义的多版本共存和灰度发布
- **导入导出**：支持JSON格式的流程定义导入导出

### 轻量级流程执行引擎
- **高性能执行**：基于内存的状态机，支持高并发流程实例执行
- **灵活路由**：支持条件分支、并行分支、包容分支等多种路由模式
- **异常处理**：完善的异常捕获和处理机制，支持重试和补偿
- **事务管理**：支持分布式事务和最终一致性保证

### 任务管理中心
- **待办任务**：支持任务的认领、完成、转办、委派等操作
- **已办任务**：查看历史任务处理记录和审批意见
- **加签功能**：支持前加签和后加签，灵活调整审批流程
- **退回机制**：支持向任意节点退回，重新处理流程

### RBAC权限控制
- **角色管理**：支持多级角色体系和继承关系
- **数据权限**：基于部门、岗位的数据范围控制
- **三员管理**：管理员、安全官、审计员职责分离
- **细粒度授权**：支持按钮级别的操作权限控制

### 监控审计系统
- **访问日志**：记录所有HTTP请求的详细信息
- **操作日志**：记录关键业务操作的审计轨迹
- **流程监控**：实时监控流程实例的执行状态和性能指标
- **Webhook回调**：支持在流程事件发生时回调外部系统

## 快速开始

### 环境要求

**后端环境**
- JDK 11+ (推荐 JDK 17)
- Maven 3.6+
- MySQL 8.0+
- Redis 6.0+ (可选)

**前端环境**
- Node.js 16+
- npm 或 yarn
- Git

### 后端部署

#### 1. 克隆项目
```bash
git clone https://github.com/your-org/workflow.git
cd workflow
```

#### 2. 配置数据库
```sql
-- 创建数据库
CREATE DATABASE workflow_db DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

-- 导入初始数据
USE workflow_db;
SOURCE flow-engine/src/main/resources/db/schema.sql;
SOURCE flow-engine/src/main/resources/db/data.sql;
```

#### 3. 配置应用参数
编辑 `flow-engine/src/main/resources/application.yml`:
```yaml
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/workflow_db?useSSL=false&serverTimezone=Asia/Shanghai
    username: root
    password: your_password
    driver-class-name: com.mysql.cj.jdbc.Driver
  
  redis:
    host: localhost
    port: 6379
    database: 0
    timeout: 3000ms

server:
  port: 8080
  servlet:
    context-path: /api
```

#### 4. 编译打包
```bash
cd flow-engine
mvn clean package -DskipTests
```

#### 5. 启动服务
```bash
java -jar target/flow-engine-1.0.0.jar
```

### 前端部署

#### 1. 安装依赖
```bash
# 安装流程设计器依赖
cd flow-designer
npm install

# 安装后台管理系统依赖
cd ../flow-web
```

#### 2. 开发环境运行

```bash
# 运行后台管理系统 (端口: 3001)
```

```bash
# 构建流程设计器
cd flow-designer
npm run build

# 构建后台管理系统
cd flow-web
npm run build
```

## 核心组件详解

### 流程定义与版本管理

流程定义是工作流的核心元数据，描述了业务流程的结构和执行逻辑。系统提供了完整的流程定义生命周期管理。

#### 流程定义结构
```json
{
  "id": "leave_approval",
  "name": "请假审批流程",
  "version": "1.0",
  "nodes": [
    {
      "id": "start",
      "type": "start",
      "name": "开始节点",
      "config": {}
    },
    {
      "id": "manager_approval",
      "type": "user_task",
      "name": "经理审批",
      "config": {
        "assignee": "${dept.leader}",
        "formKey": "leave_form"
      }
    },
    {
      "id": "end",
      "type": "end",
      "name": "结束节点",
      "config": {}
    }
  ],
  "edges": [
    {
      "id": "edge1",
      "source": "start",
      "target": "manager_approval",
      "condition": ""
    },
    {
      "id": "edge2",
      "source": "manager_approval",
      "target": "end",
      "condition": ""
    }
  ]
}
```

#### 版本管理策略
- **多版本共存**：同一流程定义支持多个版本同时存在
- **灰度发布**：支持按租户或业务线进行版本灰度发布
- **回滚机制**：支持快速回滚到历史版本

## 故障排查

### 常见问题诊断

#### 流程无法启动
**问题现象**：调用启动接口返回错误或流程无响应
**排查步骤**：
1. 检查流程定义版本是否正确
2. 验证必填变量是否完整
3. 查看解析器日志确认JSON格式正确
4. 检查数据库连接是否正常

#### 任务不可见
**问题现象**：用户看不到自己的待办任务
**排查步骤**：
1. 确认用户角色和权限配置
2. 检查数据权限范围设置
3. 验证任务分配逻辑
4. 查看权限评估日志

#### 节点执行失败
**问题现象**：特定节点执行时报错
**排查步骤**：
1. 检查节点处理器实现
2. 查看操作日志中的异常堆栈
3. 验证节点配置参数
4. 测试外部服务调用

#### 性能问题
**问题现象**：系统响应缓慢或内存溢出
**排查步骤**：
1. 分析慢查询SQL
2. 检查数据库索引使用情况
3. 监控JVM内存使用
4. 优化热点代码路径

本项目提供了一个完整的企业级工作流引擎解决方案，具有以下核心优势：

### 技术优势
- **轻量化架构**：基于Spring Boot的单体架构，部署简单，运维成本低
- **高扩展性**：插件化的节点处理器设计，支持灵活的自定义扩展
- **强安全性**：完善的RBAC权限控制和三员管理机制
- **可观测性**：内置全面的监控、审计和日志记录能力

### 业务价值
- **降低开发成本**：可视化设计器大幅降低流程开发门槛
- **提高交付效率**：标准化的流程模板和组件复用
- **增强业务敏捷性**：快速响应业务流程变更需求
- **保障合规性**：完整的审计追踪和权限控制

### 适用场景
- **企业审批流程**：请假、报销、采购等常见审批场景
- **工单流转系统**：客服工单、运维工单等任务流转
- **订单履约流程**：电商订单、供应链管理等复杂业务流程
- **合同签署流程**：电子合同、法务审批等合规性要求高的场景

通过持续的技术创新和功能完善，本项目将继续为企业级业务流程自动化提供更加强大、易用、可靠的解决方案。
