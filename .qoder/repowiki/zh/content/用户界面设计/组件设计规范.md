## 引言
本规范面向Vue前端工程，目标是统一组件开发、复用、状态管理、样式组织、表单设计、测试与性能优化实践。结合仓库中现有前端工程（flow-web），给出可落地的命名约定、目录组织、API契约、主题变量与响应式策略，以及基于Pinia的状态管理模式和表单验证最佳实践。**最新更新**：增强了组件规格说明，新增了可调整大小表格功能和标准化的表格行为模式。

## 项目结构
当前前端工程采用按功能域划分的目录组织方式：
- src/components：通用与业务组件（当前为空，建议逐步沉淀基础组件库）
- src/layouts：布局组件（如 BasicLayout）
- src/views：页面级视图（dashboard、login、process、system、task等）
- src/stores：Pinia状态模块（user.js）
- src/styles：全局样式与主题变量（variables.css）
- src/api：接口封装与请求拦截（request.js、auth.js等）
- src/router：路由配置（index.js）
- src/composables：组合式函数（useResizableTable.js等）
- src/main.js、src/App.vue：应用入口与根组件

## 核心组件与约定
- 命名约定
  - 组件名使用大驼峰，文件名与组件名一致，后缀 .vue
  - 基础组件以 Base 或 U 前缀区分（如 BaseButton、UInput）
  - 业务组件按领域命名（如 ProcessDesigner、TaskList）
  - 组合式函数以 use 开头（如 useForm、usePagination、useResizableTable）
- 文件组织
  - 单文件组件（SFC）内顺序：template → script → style
  - 子组件与样式尽量就近放置；公共样式放入 styles 目录
  - 路由懒加载：views 下页面按需引入
- Props 与事件
  - Props 必须声明类型、默认值与校验规则
  - 事件命名使用小写+连字符（如 on-submit、on-change）
  - 避免在组件内部直接修改父级数据，通过 emit 通知
- 插槽与作用域插槽
  - 提供具名插槽与默认插槽，便于扩展
  - 作用域插槽暴露必要字段，保持最小暴露原则
- 组件文档
  - 每个组件配套 README 或注释说明用途、Props、Events、Slots、示例

## 架构总览
前端整体采用"路由驱动 + Pinia 状态 + API 封装"的轻量架构：

- api/* 封装 HTTP 请求，统一处理鉴权、错误码与重试
- composables/* 提供可复用的组合式函数（如表格功能）

## 可调整大小表格组件规范

### 概述
可调整大小表格功能是项目中新增的核心表格组件能力，通过 `useResizableTable` 组合式函数提供统一的表格列宽调整体验。该功能支持用户自定义列宽、持久化存储和响应式适配。

### 核心特性
- **列宽调整**：支持鼠标拖拽调整列宽，实时预览效果
- **宽度持久化**：自动保存用户设置的列宽到 localStorage
- **响应式适配**：根据屏幕尺寸自动调整表格行为
- **性能优化**：使用防抖技术优化拖拽性能
- **无障碍支持**：键盘操作支持和屏幕阅读器兼容

### 使用方法

#### 基础用法
```javascript
import { useResizableTable } from '@/composables/useResizableTable'

const { 
  tableRef,
  columns,
  handleColumnResize,
  resetColumnWidths 
} = useResizableTable({
  storageKey: 'table-columns',
  minWidth: 50,
  maxWidth: 500
})
```

#### 在模板中使用
```vue
<template>
  <div ref="tableRef">
    <table>
      <thead>
        <tr>
          <th v-for="column in columns" :key="column.key">
            {{ column.title }}
            <div class="resize-handle" @mousedown="handleColumnResize($event, column.key)">
              <span></span>
            </div>
          </th>
        </tr>
      </thead>
      <tbody>
        <!-- 表格内容 -->
      </tbody>
    </table>
  </div>
</template>
```

### API 参考

#### useResizableTable 参数
| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| storageKey | string | 'table-columns' | 本地存储键名 |
| minWidth | number | 50 | 最小列宽 |
| maxWidth | number | 500 | 最大列宽 |
| initialWidths | object | {} | 初始列宽配置 |

#### 返回值
| 方法/属性 | 类型 | 说明 |
|-----------|------|------|
| tableRef | Ref | 表格容器引用 |
| columns | ComputedRef | 计算后的列配置 |
| handleColumnResize | Function | 处理列宽调整 |
| resetColumnWidths | Function | 重置所有列宽 |
| isResizing | Ref | 是否正在调整中 |

### 样式规范
```css
.resize-handle {
  position: absolute;
  right: 0;
  top: 0;
  bottom: 0;
  width: 5px;
  cursor: col-resize;
  background: transparent;
  transition: background 0.2s;
}

.resize-handle:hover {
  background: rgba(0, 123, 255, 0.3);
}

.resize-handle.active {
  background: rgba(0, 123, 255, 0.5);
}
```

### 最佳实践
1. **合理设置列宽范围**：根据内容类型设置合适的 min/max 宽度
2. **使用有意义的 storageKey**：为不同表格使用唯一的存储键
3. **提供重置功能**：允许用户恢复默认列宽
4. **移动端适配**：在小屏幕上禁用列宽调整功能
5. **性能考虑**：大数据表格使用虚拟滚动配合列宽调整

## 依赖关系分析
- 组件耦合
  - 布局与路由强耦合（菜单、面包屑依赖路由元信息）
  - 页面与API弱耦合（通过接口层抽象，便于替换实现）
  - 页面与状态管理松耦合（通过Pinia actions/getters）
  - 表格组件与组合式函数解耦（通过useResizableTable提供能力）
- 外部依赖
  - 路由：vue-router
  - 状态：Pinia
  - HTTP：axios（由 request.js 封装）
  - UI库：按需引入（建议）
- 潜在循环依赖
  - 避免在组件中直接引用其他组件的store实例，统一通过模块导出
  - 组合式函数不依赖具体组件实现，保持独立性

## 性能考虑
- 路由懒加载：为大型页面启用分块加载，减少首屏体积
- 组件按需加载：第三方库按需引入，避免全量打包
- 列表虚拟化：大数据表格/列表使用虚拟滚动
- 图片与资源优化：压缩、懒加载、CDN
- 计算与监听优化：合理使用 computed/watch，避免深层监听
- 请求优化：防抖/节流、并发控制、缓存策略
- 主题与样式：CSS变量与模块化，减少重复样式
- **表格性能优化**：使用防抖技术优化列宽调整，避免频繁DOM操作

## 故障排查指南
- 网络与鉴权
  - 检查 request.js 拦截器是否正确注入 token 与错误码处理
  - 确认登录成功后用户状态是否持久化与刷新后恢复
- 路由与权限
  - 检查路由 meta 与导航守卫逻辑，确保未授权页面不可达
- 表单与交互
  - 校验规则是否覆盖所有输入场景
  - 错误提示是否清晰且可定位到具体字段
- 状态一致性
  - 跨页面共享状态是否通过 Pinia 统一管理
  - 避免在组件内直接修改全局状态
- **表格功能问题**
  - 检查 localStorage 权限和存储空间
  - 验证 storageKey 的唯一性避免冲突
  - 确认列宽调整事件绑定正确
